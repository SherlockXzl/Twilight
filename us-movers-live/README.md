# 晨昏线 · 美股隔夜与开盘

把「大市值涨幅 ≥4%、小市值涨幅 ≥10%、市值 ≤15 亿美元不看」这套口径做成网页。

> **口径是美股夜盘**（美东周日至周四 20:00–04:00 = **北京 08:00–16:00**）：
> 夜盘进行中按 `NIGHT_POLL_SECONDS` 轮询，显示**实时**夜盘数据；夜盘收盘后冻结成一份
> 收盘快照，非夜盘时间一直显示它。
>
> 非夜盘期间右上角「**立即刷新**」会置灰（2026-09-23 按用户要求）—— 那份收盘快照已经定型，
> 刷新也拿不到新东西；按钮亮着只会让人以为「点一下有新数据」。置灰后鼠标悬停有原因说明，
> 夜盘一开始会自动点亮。

- 后端：Python **仅标准库**（零依赖），自带交易时段判断、后台定时抓取、内存缓存
- 前端：原生 HTML/CSS/JS（无框架、无 CDN），搜索筛选、分档、自选增删、输入建议
- 数据源：夜盘行情走 **Alpaca**（免费 Paper 账号，`feed=overnight`）；**Finviz** 负责域（哪些票要扫）、市值、板块/行业。详见「夜盘口径与数据源」

## 快速开始

```bash
cd us-movers-live
python3 server.py          # 打开 http://127.0.0.1:8787
```

离线看界面（不联网，用假数据）：

```bash
SOURCE=mock python3 server.py
```

## 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| `SOURCE` | `finviz` | `finviz`（实时）/ `mock`（离线演示） |
| `SHOW_DOWN` | `0` | 是否同时看下跌档。`0` = 只看上涨（默认），`1` = 涨跌都看。设为 `1` 会多抓两档，**请求量约翻倍** |
| `BIG_MIN_CAP_USD` | `10000000000` | 大市值档下限（100 亿美元） |
| `MID_MIN_CAP_USD` | `1500000000` | 小市值档下限（15 亿美元） |
| `BIG_PCT` / `MID_PCT` | `4` / `10` | 两档涨幅阈值（**含等于**：≥4% / ≥10%） |

口径改动只需改环境变量，前后端和 `screening.py` 共用同一份阈值，不会出现"页面写的和实际算的不一致"。

## 接口

| 路径 | 说明 |
|---|---|
| `GET /api/movers` | 全量结果（四张分档表 + 剔除对照 + meta） |
| `GET /api/morning` | 早盘总结的复盘数据（只读 `data/morning.json`） |
| `GET /api/quote?codes=AAPL,BRK.B` | 按代码精确取行情，给「个人关注池」里用户自选的票用。**全站唯一由页面发起的取数**（理由见下）。取数失败也返回 200，用 `ok:false` + `message` 表达 |
| `GET /api/symbols?q=AAP&limit=8` | 美股代码搜索，给关注池输入框的**即时建议**用。全美约 12.8k 条代码（含公司名），本地目录、毫秒级。代码库没准备好时返回 `ok:false` + 「正在准备」 |
| `GET /api/reasons` | 驱动原因（只读 `data/reasons.json`，缺失时回退最近一份早盘复盘的 driver） |
| `GET /api/duality` | 期股双面页的历史日线（黄金组 / 白银组共 11 只 × 约 800 根，含 `groups` 分组定义）。**一次给全量、区间由前端裁**（见「期股双面页」一节）。`?force=1` 绕过服务端缓存 |
| `GET /api/refresh` | 强制立刻重抓一次 |
| `GET /api/status` | 交易时段、口径、数据源。口径给**两份**：`criteria` 是人类可读的说明文案，`criteriaValues` 是数值版（`bigMinCap` / `midMinCap` / `bigPct` / `midPct`），供前端分档 |
| `GET /healthz` | 健康检查 |

`meta` 里带了取数时刻的**两个口径** —— `fetchedAt`（北京时间 UTC+8）与 `fetchedAtEt`（美东）——
以及 `snapshot`（口径：`basis` = `night_live`/`night_close`、`sessionDate`）、
`requestsTotal`（累计请求数）、`errors`（分组级失败原因）。

两个口径都给，是为了让「页面显示」和「排障」各取所需：页头右上角的**取数时间徽章显示
北京时间**（`fetchedAt`，2026-09-24 按用户要求从美东改过来），而判断「夜盘场次 / 是否在场内」
仍走美东口径（那是夜盘唯一的权威时区）。
这两个字段都是**不带时区标记**的 `"YYYY-MM-DD HH:MM:SS"` 字符串 —— 前端只做字符串截断，
**不要 `new Date()` 再格式化**，否则会按浏览器本地时区解析而产生整体偏移，
且错的时间戳看起来完全正常。由 `tools/test_polling.js` 第 12 节钉住。

## 夜盘口径与数据源（2026-09-22 按用户要求改）

**本页的口径是「美股夜盘」**，不是常规时段收盘：

| | 时段（美东） | 对应北京时间（夏令时） |
|---|---|---|
| **夜盘** | 周日至周四 **20:00 – 次日 04:00** | **08:00 – 16:00**（收盘正好是下午 4 点）|
| 盘前 | 04:00 – 09:30 | 16:00 – 21:30 |
| 常规 | 09:30 – 16:00 | 21:30 – 04:00 |
| 盘后 | 16:00 – 20:00 | 04:00 – 08:00 |

（来源：富途官方交易时间说明；夜盘由 Blue Ocean ATS / BOATS 撮合，是**独立的第四个时段**。）

对应的行为：

- **夜盘进行中** → 每 `NIGHT_POLL_SECONDS`（默认 180s）扫一轮，页面显示**实时**夜盘数据
- **夜盘已收盘** → 冻结一份收盘快照（`data/night_close.json`），非夜盘时间一直显示它。
  收盘后**会补扫最后一轮**把真正的收盘价冻住 —— 轮询是离散的，不补这一刀冻下来的
  就是"收盘前几十秒"的值，而且看不出来。

涨跌幅 = **夜盘最新成交价 ÷ 前一个常规交易日收盘 − 1**（即"隔夜累计涨幅"）。
不用"夜盘开盘价"当基准，是因为那样会漏掉**盘后（16:00–20:00 ET）**那一段 ——
而财报行情主要就发生在盘后。

### 为什么不能用 Finviz 的数据源

Finviz 的涨跌幅**一律是常规时段的**，与夜盘无关。实测（2026-09-22）：

- 免费档报价页里扩展时段是**关着的**：内嵌配置 `"premarket":0,"aftermarket":0`；
  筛选器的全部过滤器键里没有任何 `premarket`/`aftermarket`/`overnight`
- **连 Elite 也不够**：Elite 的扩展时段只到盘前 04:00–09:30 与盘后 16:00–20:00 ET，
  美东 `20:00–04:00` 那段压根不在它的数据模型里
- 免费档行情还有 15–20 分钟延迟

Finviz 仍然在用，但只负责 **域（哪些票要扫）+ 市值 + 板块/行业**。

### 夜盘行情来自 Alpaca（免费 Paper 账号）

免费档就带 `feed=overnight`（官方文档：Latest Bars、**Latest Quotes (real-time indicative)**、
Latest Trades (15-minute delayed)、Snapshots）。密钥放项目根目录 `.env`（已被 `.gitignore` 忽略）：

```
ALPACA_KEY_ID=...
ALPACA_SECRET_KEY=...
```

注册要点：Alpaca **Paper Only 账号全球可注册、免费、只需邮箱**（官方原文：
“Anyone globally can create an Alpaca Paper Only Account”）。需要护照与审核的是 live 实盘账户，这里用不上。

### 六个实测出来的坑（每条都会**静默**出错，代码注释里都有）

1. **`feed=overnight` 只在夜盘进行中可用**；结束后还用会 `400 invalid feed: overnight`，
   必须换 `feed=boats`。
2. **`feed=boats` 只有 1 分钟及以下粒度能取**：`timeframe=1Day` 会
   `403 subscription does not permit querying recent BOATS data`；`1Min` 正常
   （实测拿到 293 根，正好覆盖夜盘 `00:00Z–07:59Z`）。本项目不走这条路。
3. **⚠️ 夜盘快照里的 `prevDailyBar` 不是常规收盘价**，是**上一个夜盘**的收盘。
   实测 AAPL：overnight 的 `prevDailyBar.c = 335.74`，而常规上一收盘是 `339`，两者不等。
   照搬它算涨跌幅 → 语义完全错且不报错。
4. **`limit` 是「整个请求的 bar 条数上限」，不是每只票的条数**；多代码日线会分页
   （`next_page_token`）。不翻页就**静默截断**：8 只只回 2 只，看起来像"这些票没数据"
   （实测现场：BRK.B 曾被误判为"日线停在 9/11"，单代码请求才露馅）。
5. **陈旧成交价**：夜盘收盘后快照里仍留着**上一次夜盘**的成交。不校验窗口就会把
   昨天的价当"实时价"，页面看起来一切正常 → `alpaca._price_in_window()` 强制校验。
6. **基准价不能用 Finviz 的 Price**：常规时段内它是**盘中价**（实测 AAPL 给 342.89 而不是
   收盘 339）。改用 `alpaca.ref_closes()` —— 它从快照的两根日线里按**时间戳**挑
   "截止夜盘开始前最近那一根"，于是**无论什么时候调都对**（盘中也照取不误），
   并且带**新鲜度守卫**（过期收盘价宁可不要，免得算出一个看着正常的错误涨跌幅）。

### 一轮扫描的成本

| 步骤 | 实测 |
|---|---|
| 夜盘快照（批量 500/请求，8 路并发） | 全市场约 86 秒 |
| 基准价（feed=iex 快照，同样分批并发） | 每轮现取，约 1–2 分钟（可后续缓存优化）|
| 域缓存爬取（Finviz，按市值降序翻页，跌破下限即停） | 实测 **约 6 分钟**（117 页 / 2329 只，约 3.1 秒/页），一天一次，跑在独立后台线程里 |

域缓存**刻意不放在取数路径上**：一次爬取要几分钟（被限速时更久），塞进任何一轮轮询都会把那一轮卡住。
它由 `night_fetch.universe_loop()` 独立维护；没缓存期间 `scan()` 会如实报"无域缓存"，
页面显示等待，而不是假装"今天没有异动"。

## Finviz 用在哪（域 / 市值 / 板块）

先把验证过程说清楚，避免以后换源时踩同样的坑：

**FMP（Financial Modeling Prep）**：接口正规、字段权威，但它的 `company-screener` **只支持按市值/价格/成交量/beta/股息/板块筛选，不支持按涨跌幅筛选**。要拿涨跌幅只能"先全量取股票池、再批量查行情"，按免费额度 250 次/天算，一轮刷新就要 30 次左右，**60 秒刷新在免费额度下不可能**。适合做基本面通道，不适合做这个看板的引擎。

**Yahoo Finance**：`query2.finance.yahoo.com/v1/finance/screener` 支持 `percentchange` + `intradaymarketcap` 条件，本是最理想的免费源。**但实测从中国大陆网络访问返回 403**（页面明确提示"2021 年 11 月 1 日起中国大陆不再提供 Yahoo 服务"），本机/国内服务器均不可用。

**Finviz**：`finviz.com/screener.ashx` 的筛选表达式同时支持涨跌幅与市值档位，一次请求就返回 代码 / 公司 / 板块 / 行业 / 国家 / 市值 / 价格 / 涨跌幅 / 成交量 全套字段。

用到的筛选表达式：

| 分组 | 表达式 | 本页实测涨幅范围 |
|---|---|---|
| 大市值涨 | `cap_largeover,ta_change_u3` | 3.16% ~ 14.35%（源层留余量，代码层卡 ≥4%） |
| 小市值以上涨 | `cap_smallover,ta_change_u9` | 9.84% ~ 18.40%（源层留余量，代码层卡 ≥10%） |
| 大市值跌（默认关闭） | `cap_largeover,ta_change_d4` | −4.02% ~ −7.96% |
| 小市值以上跌（默认关闭） | `cap_smallover,ta_change_d10` | −10.02% ~ −15.00% |

### 三个必须记住的坑

1. **小市值档不能用 `cap_midover`**。它是"$2B 及以上"，会把百亿以上标的也带进来，按市值分档后全落进大市值表，小市值表恒为空。必须用 `cap_smallover`（≥$300M）取回后由 `screening.classify` 分档。
2. **小市值档必须按市值降序取数**（`o=-marketcap`）。若按涨跌幅降序，涨幅最大的永远是微盘股，15–100 亿的标的会沉到十几页之后。
3. **源层筛选要比目标阈值松 1 个百分点**。用户口径是「涨幅 **≥** 4% / **≥** 10%」，而 Finviz 的 `ta_change_uN` 粒度是 1 个百分点，**实测无法确认恰好在阈值上的标的是否被包含**（`u3` 最小 3.16%、`u9` 最小 9.84%，样本里都没有贴边界的值）。所以取数用 `u3`/`u9` 留出余量，再由 `screening.classify` 用精确的 `>=` 判定。少了任何一半，收盘正好 4.00% 的票都可能被漏掉。

### 已知限制（务必了解）

- **属于页面抓取**，不是官方接口。Finviz 一旦改版或限流（返回 403/429），需要更新 `providers.py` 里的解析正则；代码里已做限流识别与中文报错提示。
- **一天一轮请求，对免费源毫无压力**。默认只看上涨时一轮约 3–8 次请求（`SHOW_DOWN=1` 翻倍），从「开市期间每 60 秒一轮、盘中数千次/天」降下来，顺带彻底消除了被限流的风险。
- **夜盘行情靠自己算，不走 Finviz**（见上一节）。Finviz 只提供域、市值、板块/行业 ——
  它的涨跌幅是常规时段的，与夜盘无关，连 Elite 也不覆盖美东 20:00–04:00。
- **域缓存一天重建一次，实测约 6 分钟**（117 页 / 2329 只；Finviz 有时会把请求限速到十几秒一页，那就更久）。
  它跑在独立后台线程，失败就保留上一份并退避重试，不影响服务。
- **夜盘流动性远低于常规时段**：大量票整段没有成交，会被直接跳过（不当成"0% 没动"）。
  所以名单会比常规时段稀疏，也比常规时段更容易跳。
- **免费档的夜盘报价是"指示性报价"（indicative），不是逐笔成交**；成交明细延迟 15 分钟。
  看异动够用，但别当成精确成交价。

## 部署

### 方式一：任意支持容器的后端主机（推荐）

本服务零依赖，`Dockerfile` 已备好：

```bash
docker build -t us-movers-live .
docker run -p 8787:8787 us-movers-live
```

`render.yaml` 可直接用于 Render 一键部署（免费档即可，但免费实例会休眠）。Railway / Fly.io / 自己的云主机同理。

### 方式二：纯静态托管（有硬限制）

**CloudStudio 等静态托管只支持纯前端，跑不了这个后端。** 而且实测 **Finviz 不返回 CORS 头**，浏览器无法直接调用 —— 所以纯静态页面没有办法复用 Finviz 引擎。

如果一定要纯静态可分享，只有一条路：改用 **FMP（它返回 `access-control-allow-origin: *`）**，把 Key 存在访问者自己的浏览器 localStorage 里，由页面直接调 FMP。代价是：

- 每个访问者要自己准备一个 FMP Key
- 受"筛选接口不支持涨跌幅"限制，需要"股票池 + 批量行情"两步，额度消耗大
- 免费 250 次/天大约只够十几轮刷新

这是可做的，但需要你确认要这条路线，并且要提供一个 FMP Key 用于联调（我无法在没有 Key 的情况下验证这段代码）。

### 方式三：本机运行 + 公网隧道（拿到固定链接）

在本机跑服务，用 Cloudflare 隧道把 `127.0.0.1:8787` 暴露到公网。两条路：

| | 地址 | 说明 |
|---|---|---|
| **临时**（quick tunnel） | `https://<随机>.trycloudflare.com` | `bash tools/start.sh` 即可，**不需要任何账号**。但每次重启换域名 |
| **固定**（命名隧道） | `https://movers.你的域名.com` | 重启/换网络都不变，可以直接发出去 |

#### 固定链接怎么配

**当前线上地址：<https://twilight-market.trade>**（隧道名 `chenhunxian-movers`）

**硬约束：Cloudflare 的固定链接必须绑定一个托管在 Cloudflare 的域名。** 没有域名只能用 quick tunnel，而它天生随机 —— 这是产品限制，绕不过去。

三步：

```bash
# ① 一次性：浏览器里选中你要用的域名（这一步必须交互，脚本代劳不了）
cloudflared tunnel login

# ② 配置固定链接（幂等，可重复跑）
bash tools/tunnel-setup.sh twilight-market.trade

# ③ 把两个进程交接给 launchd（开机自启 + 崩溃自启）
bash tools/golive.sh
```

第 ② 步会依次做：检查本地服务 → 检查登录态 → 建/复用命名隧道 → `route dns` 写入 CNAME →
生成 `~/.cloudflared/config.yml` → 把 launchd plist 从 quick tunnel 换成命名隧道 → 等待握手 → 端到端验证。

第 ③ 步必须在**你自己的终端**里跑 —— AI 助手的沙箱执行 `launchctl bootstrap` 会被系统拒绝
（`Bootstrap failed: 5: Input/output error`）。它会先 `bootout` 卸掉托管实例，再收掉仍占着 8787 / 20241
端口的野进程（开发期间从会话里起的那些），然后重新 `bootstrap`。

之后 `bash tools/share-url.sh` 会自动认出固定链接模式并打印地址。

**为什么非要有第 ③ 步**：从会话/临时终端里起的进程，会话一结束就被系统连带回收
（`nohup`、`disown`、`setsid` 都挡不住），症状是"某天打开链接发现打不开了"、
日志停在某一刻且**没有任何报错**。只有 launchd 的 `RunAtLoad` + `KeepAlive` 才真正长期活着。

**域名从哪来**：Cloudflare Registrar 按成本价卖（`.com` 约 $9.15/年，**注册价 = 续费价**，含免费 WHOIS 隐私），
注册时自动接管 DNS，不用手动改 NS。入口 <https://domains.cloudflare.com/>。

**排障顺序**（每一步失败对应一类不同的故障）：

```bash
bash tools/share-url.sh     # ① 本机服务在监听？ ② 隧道连着 Cloudflare？ ③ 解析出真实 IP？ ④ 端到端 200？
tail -f /tmp/cfd-tunnel.log # 隧道自己的日志
launchctl list | grep chenhunxian
```

两个容易踩的点：

1. **本机 DNS 被代理接管成 fake-ip（`198.18.x.x`）**，直接 `curl 域名` 永远不通，
   会被误判成"隧道坏了"。必须先经 DoH 拿真实 IP 再 `curl --resolve`。
   这段逻辑抽在 `tools/lib-doh.sh`（`share-url.sh` 与 `tunnel-setup.sh` 共用），
   **多源依次试、国内源优先** —— 实测这台机器上 `1.1.1.1` / `8.8.8.8` / `dns.google`
   全都不通（`dns.google` 连 `example.com` 都返回空响应），`dns.alidns.com` / `doh.pub` 才是稳的。
2. **地址分配出来 ≠ 隧道握手完成**，这中间去访问会得到 502。
3. **刚写入的 DNS 记录不会立刻解析出来**（实测约 1~5 分钟），而且本机路由器还会缓存
   着注册域名之前的 NXDOMAIN。所以 `tunnel-setup.sh` 的端到端验证带 3 轮重试，
   别急着判定配置失败。

## 驱动原因从哪来

两张表都有一列「驱动原因」（早盘页叫个股异动榜，夜盘异动原先那列是「查原因」的外链）。
这一列**不由页面生成**——页面只读，原因是分析后的结论，规矩和早盘复盘一样：脚本取素材、
智能体下判断，谁也不许猜。

```
reason_fetch.py                 # 机械部分：当前榜单 + 每只票的近期新闻标题（finviz 个股页）
      ↓ 素材 JSON
智能体分析（读标题、必要时补搜）  # 判断部分：产业因子 · 个股催化剂，一句话
      ↓
data/reasons.json               # 落盘
      ↓ GET /api/reasons
夜盘异动页「驱动原因」列
```

几个约定：

- **两级来源**：`/api/reasons` 先读 `data/reasons.json`（夜盘自己的），再对缺失的代码回退到
  最近一份 `data/morning.json` 的 `movers[].driver` —— 同一只票两页显示同一句话，不会各说各的。
  两边都没有就显示「待确认」，不编造。
- **原因比行情慢，但要跟着行情重取**（2026-09-29 改，此前是"进页面取一次"）：
  `evening.js` 的 `loadReasons` 由 `onData` 调用，每轮行情都重取一次这份小 JSON。
  起因是补原因的自动化现在**每 2 小时（工作日）**也跑，实际落点是
  08:13 / 10:13 / 12:13 / 14:13（盘中补）+ 16:13（收盘收口），
  长开的看板不重取就会永远停在打开那一刻，补进去的原因要手动刷新才看得见。
  三处细节：在飞的请求不重发（`reasonsLoading`）、**内容没变就不重画**（表格是整块重建的，
  白重画会把横向滚动顶回最左边）、进页面时**不再单独取一次**（原因只出现在表格里，而表格要等首轮行情）。
- **键是股票代码**，所以快照过期只会让个别行退回「待确认」，不会串行。
- 无法从新闻确认的写法要标「（推断）」，例如「随板块联动走强（推断）」。

`data/reasons.json` 结构：

```jsonc
{
  "meta": { "sessionDate": "2026-09-22", "sessionLabel": "9月22日 盘前",
            "generatedAt": "…", "generatedBy": "…", "basis": "finviz 新闻标题 + 公司公告" },
  "reasons": {
    "VICR": { "driver": "AI 电源链 · 上调 Q3 2026 营收指引…",
              "basis": "Vicor Shares Jump Nearly 9.9% After Company Raises Third-Quarter Revenue Outlook" }
  }
}
```

> 想让它自动跑：设一个盘后定时任务，先跑 `python3 reason_fetch.py -o /tmp/raw.json`，
> 再由智能体读素材、写 `data/reasons.json`。取数与判断分开的理由与 `MORNING.md` 里写的相同。

页面上有两个东西都叫「A 股映射」，**口径、数据、渲染器全都不同** ——
不要合并渲染器，也不要拿一处的说法去描述另一处：

| 数据 | `data/us_business_map.json` → `GET /api/us-business-map` | `data/reasons.json` 每条原因里的 `aShareMap` 字段 |

### 悬停卡：业务相似度（2026-09-28 早盘页起 · 2026-09-29 夜盘页起）

把光标放在**美股代码或公司名**上，弹一张小卡，列出 A 股里业务相似的公司（代码 + 名称），
末行固定是那句「业务相似对标，不代表存在供应链、客户或股权关系」——
**这句一个字都不能省**：少了它，「歌尔股份」会被读成「苹果的供应商」。

```
data/us_business_map.json → GET /api/us-business-map（引用式三表 rows / industries / overrides）
      ↓
static/bizmap.js   装配（of）+ 接线与预热（attach / warm / canHover）
      ↓
static/biztip.js   悬停卡本身（定位 / 延迟 120ms / 只给代码与名称）
```

夜盘异动页 2026-09-29 之前是「A 股映射」列（每行一个「点击查看」按钮 → 弹窗），
同日按用户要求改成与早盘页**同一套**悬停卡。改的是那一列，不是那个能力。

几个刻意的选择（改动前先想清楚，`tools/test_evening_biztip.js` 与
`tools/test_morning_biztip.js` 会拦住）：

- **预热而不是悬停时再取**：整包 426KB（gzip 后约 95KB），等光标落上去才开始下载，
  第一格必然什么都看不到。
- **认版本号**（`BizMap.SCHEMA` ↔ `server.py` 的 `BUSINESS_MAP_SCHEMA`）：服务端换了响应结构
  而进程没重启时，接口照样 200、rows 一家不少，只是缺 `industries`/`overrides` ——
  照单全收的话每一格都会静默变成"这家没有对标"，而数据其实躺在磁盘上。
- **触屏（hover:none）不取这份数据**：那个功能在触屏上根本触发不了，白搬 426KB。
- **拿不到就什么都不显示**，不给"载入中 / 暂无"的占位卡 ——
  「这家在 A 股没有对标」只有在数据到手时才成立，不能拿它顶替"没加载"。
- **光标保持原样**（2026-09-28 用户要求去掉 `cursor:help` 的问号）：那等于给一片死文字
  加了"这里能点"的暗示，而它既点不动、也只是补充信息。

接线与预热的守卫**只写在 `static/bizmap.js` 一处**（`attach` / `warm` / `canHover`），
两个页面各只留一层薄包装 —— 这几条守卫写错时都不报错、只是功能静默失效，两份实现必然漂移。

数据里照写不误 —— 分析时该判断就判断，只是弹窗不显示它。

## 站点标（左上角 logo + 「晨昏线」）

页面最左上角是站点标：`logo.png` + 站点名 + 副标题，由 `shell.js` 的 `renderSidebar` 生成，
样式在 `style.css` 的「站点标」一节。

**站点名是常规字体 + 常规颜色** —— 字体不单独声明（继承 `body` 的系统字体栈），
颜色用全站正文色 `--ink`，字重 600、字距 1.5px。跟满屏界面元件同一套，不做特殊化。

几件事都是**改错了不会报错**的类型（`tools/test_brand.js` 全盯着）：

**1. logo 用 `<img>`，不是 CSS 背景图。** 背景图在打印、右键另存、Reader 模式里都不会跟着走，
而这是全站唯一的品牌资产，值得是个真元素。`width`/`height` 同时写在标签属性上 ——
图还没解码完时，侧栏不会先塌一下再跳回来。

**2. 资产是裁边重排过的，不是原图直接缩。** 设计师给的 1254px 原图四周有不等的留白
（内容只占画布 79%），直接用会让 logo 在页面上莫名其妙地小一圈、还和文字对不齐。
现在按 alpha 包围盒裁到正方形再缩到 192px，内容占到 93%，四周留白左右各 7px、上下各 3px。
用例会**真的解开 PNG 逐像素量包围盒**来验证这一点 —— 尺寸、透明通道全都对的文件，
依然可能是一张「内容缩在中间」的图，只看文件头是看不出来的。

**3. 站点名必须够黑。** 它压在白侧栏上，唯一会静默失败的方向就是字色太浅（浅到看不见）。
用例不是查「写没写颜色」，而是把 `--ink` 读出来**算对比度**，低于 4.5:1 就挂。
这不是假想 —— 本项目真做过一次白字（见下）。

### 曾经做过、后来又撤掉的尝试（2026-09-22 当天）

站点名一度被做成「三个字三种处理」：**晨**金 · **昏**蓝（分色界落在两字之间，寓意「晨昏线」）+
**线**白底黑描边。当天按用户要求全部改回常规。**结论没丢，两条都是量出来的**，重做时直接用：

- **金色不能直接用 logo 原色。** logo 原金 `#fcb13a` 在白底只有 **1.83:1** 对比度，
  当 21px 加粗标题用也不达 WCAG 大字号下限（3:1），照搬过来字会发虚；压深到 `#c97600` 得 3.46:1。
  logo 月亮蓝 `#385999` 是 6.87:1，原色可用。
- **「线」要做白底黑描边，字体必须换成笔画均匀的黑体系。** `-webkit-text-stroke` 是**居中**画的
  （填充再盖上去，只露出 W/2 宽的外圈）。宋体横画在 21px 下只有约 1px：

  | 组合 | 结果 |
  |---|---|
  | 宋体 + 1px 描边 | 外圈 0.5px，抗锯齿后是**灰的、不是黑的**，等于没描 |
  | 宋体 + 2px 描边 | 外圈 1px 把 1px 的横画两面夹死 → **整字变成黑疙瘩**，白芯消失 |
  | 黑体 + 1.75px | 外圈 0.9px 实黑，白芯仍在 ✓ |

  宽度 1.75px 也是量出来的：按 2 倍屏统计像素，1.5px 纯黑仅 24%（偏灰）、2px 已 37%（偏重）、
  2.25px 起 44%（黑疙瘩）；1.75px = 29% 纯黑 / 21% 灰。
- 白字还有一条静默失败：**不支持 `text-stroke` 的浏览器里，白字在白侧栏上会整个消失**，
  当时配了 `@supports not (...)` 的 `text-shadow` 兜底描边。

分色/描边撤掉后，相关的三个类（`.bd`/`.bn`/`.bo`）、两个变量（`--brand-dawn`/`--brand-night`）、
兜底块**都已删除** —— 留着就是死样式，下次有人翻到会以为还是现行约定。用例专门盯这件事。

### 测量提示

细线、描边、小字号**必须用 `--dpr 2` 截图看**（`tools/visual_check.py shot ... --dpr 2`）。
1 倍下抗锯齿会把不足 1px 的线渲染成灰色，本项目实测就差点看错采样率把描边宽度改小
（1x 下像黑疙瘩、2x 下其实是干净的黑边）。像素分析同理，采样率要和屏幕一致，数字才对得上观感。

### 一个真实例子：夜盘标签「点了没反应」

标签的选中态原先是写在 `renderTabs()` 拼 HTML 的字符串里的，
而点击的处理只调了 `renderBody()` —— **表格换了，高亮没换**。
在页面还每 20 秒轮询一次的那会儿，这个问题自己会消失（下一轮 `renderTabs` 顺手纠正），
所以一直没被发现；后来轮询被去掉/暂停之后就永久错了：
点「大市值」表格确实从 11 条变 7 条，但高亮还停在「所有」上，看着就像点击没生效。

现在选中态**只由 `paintTabs()` 一处涂**（点击时涂、数据刷新重建 DOM 后再涂），
并由 `test_evening_tabs.js` 盯住 —— 该用例做过变异测试：
把点击时的那次 `paintTabs()` 删掉，确实会挂 4 项断言。

> 这个坑在这次的"不自动更新"改版里更值一提：以前还能靠"下一轮刷新顺手纠正"掩盖住，
> 现在页面上**根本不会再有下一轮**，任何"只在下次刷新时才会纠正"的写法都会变成永久错误。
> 同类写法要一并检查（自选增删的 `paintBands`、标签 `applyTab` 都属于这一类，都已经改成点击时立即涂）。

## 早盘总结页（/morning）

左侧菜单第二项。它**不抓行情**，只读取 `data/morning.json` —— 由工作日 06:30（北京时间）的
定时任务调用 `us-stock-daily-review` 技能生成后写入。

- 数据契约与生成流程见 **[MORNING.md](./MORNING.md)**
- 机械取数脚本：`morning_fetch.py`（指数 ETF / 全市场涨幅榜 / 个人关注池）
- 服务端接口：`GET /api/morning`（只读，文件缺失或损坏时返回 `ok:false` 的中文原因，不让页面白屏）

页面以 `mode:"daily"` 挂载站点外壳：**不轮询**，页头显示 市场状态 / 复盘交易日 / **生成时间**，
**没有刷新按钮、也没有第二个时间徽章**（均为 2026-09-22 按用户要求移除）。
想拿最新数据就重新加载页面。

> **时间只保留「生成时间」**，它来自 `meta.generatedAt`，是数据文件**实际被写出的那一刻** —— 真实值。
>
> 曾短暂加过一个「读取时间」，先显示浏览器打开页面的时刻（对读者没意义：永远是"现在"），
> 后改成"每日更新时刻（当日 06:30）"。但那个 06:30 只是课表上的**名义时刻**，
> 而正常情况下自动化跑完就在 06:30 之后几分钟 —— 两个徽章会显示几乎相同的数字，
> 让人犹豫该信哪个。所以只留真实的那一个。

**标签页记忆**：「总览 / 个股 / 关注」选中哪一页会记在 `localStorage`（键名 `morning.tab`），
切到「夜盘异动」再切回来还停在原处，不会被重置回「总览」（2026-09-22 按用户要求）。
**夜盘异动页的「所有 / 大市值 / 小市值」同理**，键名 `evening.tab` —— 两页各用一个键，互不干扰。

### 两组「标签」是两种控件，不要统一（2026-09-22 按用户要求）

两页顶部那排按钮**长得像、语义完全不同**，现在是两套独立样式：

| | 早盘总结「总览 / 个股 / 关注」 | 夜盘异动「所有 / 大市值 / 小市值」 |
|---|---|---|
| 修饰类 | `.tabs--page` | `.tabs--filter` |
| 性质 | **子页面切换** —— 换的是整块内容，等于翻页 | **分档筛选** —— 只换同一张表的行，表格还在原地 |
| 样式 | 分段控件：灰色凹槽外框 + 选中项白色凸起 + 加粗 | 药丸 chip：无外框、小一号、描边轻、选中 = 实心蓝填充 |
| 前置标签 | 无 | 有「分档」二字 |

**为什么必须分开**：两者样式一样时，读者会把「所有 / 大市值」也当成换页控件，点下去发现
只是筛行、视野没动，就会判断成"点了没反应" —— 这和下面那个真实 bug 是同一类误判的两种表现：
一个是真的没生效，一个是生效了但看不出来。

页面顶部的 `#tabs` 容器各挂一个修饰类（`morning.html` → `tabs--page`，`index.html` → `tabs--filter`），
**不要在两页顶部共用同一个**。反过来，**分档 chip 是刻意共用的** —— 早盘「个股异动榜」里那个

### 个股异动榜也有分档（2026-09-22 按用户要求）

### 两张表的排序（2026-09-22 按用户要求改）

| 表 | 顺序 |
|---|---|
| 个股异动榜 | **涨跌幅降序**，涨得最多的在最上面；并列按代码升序兜底 |
| 个人关注池 | **股票代码字母序** |

**异动榜原先不是纯涨跌幅降序**，而是「巨头优先，其次按涨幅降序」。这个坑很隐蔽：
涨得最猛的多半本来就是巨头，所以**只看前几名截图，两种规则长得一模一样**。
改之前它把一只涨 33.68% 的常规异动压在了几只涨 4%–5% 的巨头下面 ——
名次和"涨得多少"脱钩了。现在巨头身份只由「★ 巨头」徽章表达，不占排序位。

**关注池原先按涨幅降序**，现在按代码。理由：关注池是「我关心的票」的固定清单，
按涨幅排会让同一只票的格子天天换位置，想找某只票得先知道它今天涨了多少，等于每次重扫一遍。
代码是稳定键，今天见过、明天还在原地。

两个实现细节：

- **排序在两处都做**，是刻意的：`morning_fetch.py` 保证写出的 JSON 自洽，
  渲染层（`morning.js` 的 `sortMovers` / `sortWatchlist`）保证页面上看到的一定是对的 ——
  数据文件每天 06:30 才更新，改了排序规则当天读到的还是旧顺序的那份。
  **两处顺序必须一致**，由 `tools/test_morning_order.js` 盯住。
- **关注池的振幅条基准不随排序变**：按全量最大 `|chgPct|` 取，不是取排完序的第一根。
  否则换排序会让同一条的长度改变，看着像涨跌幅变了。

### 关注池的自定义增删（2026-09-22 按用户要求）

> 位置：「关注」标签页（2026-09-22 从「个股」页挪出来单独成页）。

面板上方一条工具条：`[美股代码，如 AAPL / BRK.B] [添加]` ＋ 右侧「已移除 N 只，恢复」。
每个方块右上角有 `×`（悬停显形，触屏常驻）。**清单存在浏览器 localStorage 里，服务端不写**。

#### 只存增量，不存整份列表

localStorage 键 `morning.watchlist`，里面只有两个数组：

```jsonc
{ "added": ["usAAPL"], "removed": ["usINTC"] }
```

底稿始终是 `data/morning.json` 的 `watchlist`（自动化每天 06:30 重写），最终列表 =
**底稿 − removed + added**。

为什么不存整份快照：那样等于把上游的每日更新**永久屏蔽**——自动化隔天加了新票，用户这边
还是昨天那份，"编辑"就变成了"分叉"。存增量则两头都对：上游改了自动跟上，用户的增删照样生效。

`removed` 必须留着记录，否则明天数据一刷新，被删的票就自己回来了（表现成"删不掉"）。

#### 自选票的行情：全站唯一由页面发起的取数

用户加的代码不在日更 JSON 里，只能现场要一次 → `GET /api/quote?codes=…`。
服务端把两路数据合并成一行：

| 字段 | 来源 | 为什么 |
|---|---|---|
| 公司名 / 板块 / 行业 / 市值 | finviz 的 `t=` 精确查询 | 跟交易日无关，取到就行 |
| 收盘价 / 涨跌幅 | westock 日线，取**上一个已收盘交易日** | 必须与池内其它票**同一交易日**，否则盘中新增的票显示今天，老票显示昨天，同一排格子两套时间基准，比大小就是错的 |

westock 拿不到时才回落到 finviz 的盘中价，并标 `basis:"intraday"`。
服务端有 120 秒 TTL 缓存（`QUOTE_TTL_SECONDS`）与单次代码数上限（`QUOTE_MAX_CODES`，默认 40）。

三个踩过的坑：

1. **类别股的写法两个源正好相反**：finviz 用连字符（`BRK-B`），westock 用点（`usBRK.B`）。
   `fetch_quotes` 传的是**用户请求时的写法**，恰好是 westock 认的那个；finviz 那一侧靠
   "第一轮没认出且带点就再用连字符试一次"补上。**别去统一它**，一改就有一边查不到。
2. **代码不存在 ≠ 取数失败**。两个源都正常应答、只是没有这个代码 → 归 `missing`，前端提示
   "查不到这个代码"且**不给重试按钮**（再点也没用）；源本身报错才给"点击重试"。
   混成一句会让用户对着拼错的代码反复重试。
3. **取数失败时不能把已命中的缓存一起丢掉**。曾经的写法在"全部源不可用"时直接
   `return {}`，结果是"新加了一只拼错的代码"会让整池已经取到的票一起变空白。

#### 前端几个约定

- **面板恒渲染**（不像其它区块那样"没数据就不出现"）：它是唯一能往池子里加票的入口。
- 工具条与方块网格**分开两处**：增删后只重绘 `#wlHost`，不重建工具条 ——
  重建会把用户正在输入的代码和焦点一起弄丢（与异动榜把表格单独放 `#mvTableHost` 同理）。
- 自选票的行情**不持久化**：存下来只会让下次打开先看到一堆旧数字再跳变。
- 添加一只曾经被移除过的代码 = **撤销那次移除**，而不是"再加一只"；已在池中则只给提示。
- 自选票与默认池**重合时只显示一格**，且删得掉（判据是"在不在底稿"，不是"是不是自选"）。

`tools/test_morning_watchlist.js` 盯着这些（61 项断言），六向变异测试全部能抓到 ——
其中一项（`WL_STORE` 声明位置）就是变异测试之前先抓到的**真 bug**：键名写在 `var state`
之后，`wlLoad()` 执行时读到 `undefined`，自定义清单**刷新一次就全丢**，且不报任何错。
那一节是唯一"必须真的从 localStorage 读回来"的用例；其余用例都在同一会话里增删，
内存里的 state 够用，全都看不出这个错。

#### 输入时的即时建议（2026-09-22 按用户要求）

输入框里一边打字一边给代码建议：`aapl` → Apple；`semi` → 半导体相关一串；`apple` 也能命中
（名称参与匹配）。列表里点一只**直接加进池子**，不用再点「添加」。

**为什么不复用 `combo.js`**：那是「从固定列表里挑一个」（按钮触发、弹层里另有一个搜索框，
用于板块/行业筛选）；这里是「输入框本体就是要搜的词」。交互模型不同，硬套两头别扭，
所以另写 `suggest.js`，但复用同一套视觉语言。匹配也不在前端做 —— 全美代码表在服务端。

**代码表为什么不用 westock 的 `search`**（它确实有 `search` 子命令）：实测三个原因都不合适 ——
单次约 **1.5 秒**（输入建议是逐字触发的，这个延迟没法用）；`--limit` 不生效且结果混着大量
2 倍做多/做空 ETF；返回的代码还带交易所后缀（`usAAPL.OQ`）。改用 nasdaqtrader 的两份官方
符号目录（免费），**下载一次缓存 7 天**，查询 1~4ms，排名规则也能自己定（见下）。

**搜索排名**（`symbols.py` 的 `search`，三级全部可复现）：

1. **杠杆 / 反向 ETF 沉底** —— 复用 MORNING.md「必须做的过滤」那套关键词
   （`2x`/`3x`/`Bull`/`Bear`/`Short`/`Daily`/`Direxion`/`ProShares`/`Ultra` 等）。
   为什么需要：这类 ETF 极多且常**恰好占着某个短代码**。实测输 `NVD` 时，按匹配档排第一条是
   NVD（GraniteShares 2x Short NVDL Daily ETF），而用户十有八九想打 NVDA。沉底之后 NVDA 上来，
   同时不影响真正想找 ETF 的人（搜 `SOXL` / `PSI` 时它们仍是唯一或最靠前的命中）。
2. **匹配档**：代码完全相等 > 代码前缀 > 代码包含 > 名称前缀 > 名称包含。
3. **同档内正股优先于 ETF**，再按代码字母序（保证两次搜索不会换顺序）。

只做**子串**匹配，不做逐字符子序列 —— 与 `combo.js` 的 `Combo.match` 同一套语义，
全站的「模糊」是一个意思。

**客户端三件事做错了都不报错**（`test_suggest.js` 全盯着）：

- **请求竞态**：「AA」和「AAP」两次请求，慢的那个后回来会把列表覆盖成上一个词的结果。
  用自增序号作废过期响应。
- **回车不自动选中第一条**。用户打「NVD」按回车是想加 NVD，若默认高亮第一条（NVDA），
  会静默加错一只票而且看起来"成功了"。所以默认不高亮，回车 = 提交输入框原文；
  要高亮得先按 ↓。多按一次键，换掉一类静默错误。
- **点选走 mousedown 而不是 click**：click 之前输入框会先 blur、弹层先关，点在空气上 ——
  表现是"点了没反应"。`destroy()` 还必须把监听逐个摘掉（尤其挂 `document` 上那个），
  否则同一个输入框重挂后一次回车会跑两遍。

启动时**后台**构建代码目录（首次要下约 890KB / 实测 7 秒，不能卡在启动路径上）。
没准备好的那几秒 `/api/symbols` 返回「正在准备」，前端就是没有建议，不是故障。

> 用 localStorage 而不是 URL hash：左侧菜单的链接指向 `/morning`（不带 hash），
> 跨页跳转时 hash 不会跟着走，只有存储能"记得"。存的是 **key 而不是下标**，
> 以后调整标签顺序也不会串页；取不到记忆（首次访问 / 隐私模式 / 值已失效）时回落到第一个标签。

> 夜盘页比早盘页多一层：**分档是后端决定的**（`SHOW_DOWN=0` 就没有「跌」两档），
> 所以选择记忆时只做取值、不判断有效性 —— 要等第一份数据到了才知道哪些标签存在，
> 有效性由已有的"选中档失效 → 回落「所有」"那条逻辑统一兜住。
> 回落时**不写回存储**：分档可能只是这一次没返回（取数抖动，或那天该档为空），
> 保留用户原本的偏好，下次回来还能自动恢复。

### 为什么分组，而不是全画在一张图上

最省事的做法是"把两组都塞进同一张图"，但这一页的纵轴是**相对基准的涨跌幅（%）**——
金价和银价同为贵金属、日相关性还不低，混在一根轴上之后，那条 0% 基准就同时代表两种
基本面，"谁跟谁像"这件事就没法读了。所以**一组一张图**，各组的 0% 是自己的品种。

分组定义在**后端**（`duality.py` 的 `GROUPS` + 每个标的的 `group`），随 payload 一起下发
（`payload.groups`），前端据此出 tab、再按 `group` 过滤标的：

- **加一组不用动前端** —— 在 `GROUPS` 里补一条、在 `INSTRUMENTS` 里给新标的写上 `group` 即可；
  唯一要记得的是给新标的配一个颜色（`PALETTE`），没配**不报错**，会静默落到回退板、
  可能和别的线同色（`tools/test_duality.js` 有用例对齐两边的 key 集合）。
- 前端只留一份兜底（`PAGE_TABS_FALLBACK`），用在"响应里没有 groups"时；
  正常路径**一律以后端为准**。分组 key 写错一个字母不会抛异常 ——
  症状是"某只票不见了"，所以配置侧由 `tools/test_duality_source.py` 钉（见下）。
- 页面的所有渲染都走 `groupItems()`（勾选卡 / 区间计算 / 图 / 表），**不允许直接读 `S.items`**：
  两组同框正是分组要避免的事。

### 控件

| 控件 | 说明 |
|---|---|
| 分组（页面顶部 tabs--page） | 纽约金 × 黄金股 / 纽约银 × 白银股。**切换即换整块内容**（图、勾选卡、表），不是叠加 |

### 期货为什么画虚线

这一页的两面本来就是**期货**和**股票**，一组（5~6 条线）里只有一条不是股票。用线型把这一面标出来：

- **常驻** —— 不用悬停就看得到（悬停提示得动鼠标才有），这是它比"加一套图例"强的地方；
- **不依赖颜色** —— 颜色留给"哪只票"，线型回答"哪一面"；
- 判定看 `kind === "future"`，**不看名字里有没有「金」**（带「金」的票多的是）。

两个细节：0% 基准线也是虚线，所以两处的值必须分开写（基准 `4 3`、期货 `6 6`），
免得以后有人把两条混成一条、而"基准线是虚线"那条断言跟着变成永远成立的空断言；
图例（勾选卡）里的标记也从小圆点换成了**小线段**，虚线段用 `repeating-linear-gradient`
拼 —— 图例若还是圆点，"线型"这件事就只存在于图上，看的人得自己回图里去猜。

### 悬停：怎么认出"我指的是哪条线"

**问题不是"有没有提示框"，而是"这一行里哪一行对应我指着的那条线"。** 四只标的时还能拿颜色
数出来，六只之后（2026-10-08 加中国黄金 / 四川黄金）就不行了。所以悬停认线靠四条线索：

| 线索 | 做法 |
|---|---|
| **线上名称标签** | 吸附点旁**直接写出名字**（`.dp-tag`，白描边保证在线条密集处也读得清）。提示框里虽然也有名称，但它只是其中一行，眼睛得先找到它；标签贴在线本身上，视线不用离开图 |
| **线吸附** | 鼠标纵向 `LINE_SNAP = 22` 像素内最近的那条线**加粗到 3.4**、其余**压暗到 15%**。鼠标离所有线都远时不吸附，回到原来那张全表 |
| **该行置顶** | 被吸附的那一行**排到第一行**并加淡蓝底色（`.dp-tip-r--on`），其余行照常列出 —— 对比信息不能丢 |
| **稳定标识** | 名称后跟一个不随数据源变的标识：A 股是 6 位代码（`601899`），期货退回到市场名（`COMEX`） |
| **行日期** | 该行数据实际取自更早一个交易日时（这只标的当天休市）标出来，免得误以为图上那个点就是当天的 |

#### ⚠️ 提示框「永远不显示」——2026-10-08 靠真实浏览器才逮到

`.dp-tip` 的 CSS 初始态就是 `display:none`，而 JS 原来写的是 `tip.style.display = ""`
去"显示"它。**清空 inline 值等于把决定权交回 CSS**，于是又变回 `none` ——
那个提示框从上线起就没显示过，用户提了两次"悬停要有提示"，根因在这里。

症状极具欺骗性：**内容算得完全正确、DOM 里一应俱全、`innerHTML` 有几百个字符，
就是永远看不见**。而两个基于 DOM 桩的用例照样全绿 —— 桩不实现 CSS 层叠，
"有内容"就算过。两个用例里新加的那条断言（JS 给的必须是 `"block"`、CSS 必须保留
`display:none`）是**配对**的，只守一条的话，改掉另一条时它会静静地失去意义。

逮到它靠的是**真实 Chrome + 真实鼠标事件**（CDP `Input.dispatchMouseEvent`，
不是页面内 `dispatchEvent`），判据是**悬停前后该区域逐像素比对**（实测 23 万像素有差异）——
"元素存不存在"证明不了它被画出来了。这类"悬停才出现"的东西，一张 `--screenshot` 里
永远是空的，`--dump-dom` 里又永远是有的，中间那条缝很宽。

另外两处容易做错的地方，都用例钉住了：

- **压暗 / 加粗只能逐元素改属性**（`emphasize()` 里 `querySelectorAll("[data-k]")` + `setAttribute`）。
  折线是字符串拼进 `innerHTML` 的，没有可供样式钩子命中的 class；SVG 子元素也不继承父级的 `opacity`。
  每个序列元素都挂了 `data-k="<标的 key>"` —— 这是"一条 polyline ↔ 一只标的"之间**唯一**的联系。
- **标识不能用 `it.code`。** 那个字段是数据源给的：同一只票走东财是 `601899`、走腾讯是 `sh601899`，
  换个源页面上的代码就变了写法（现在落盘缓存里存的就是后者）。所以改用写死在 `INSTRUMENTS` 里的
  `note`（形如 `601899 · 铜金矿龙头`）中「·」前那段 —— 期货没有证券代码，退回市场名，
  显示 `COMEX` 反而正好说明它不是 A 股。
- **`.dp-tag` 的 CSS 里不能写 `fill`。** 标签颜色是靠 SVG 的 `fill` **呈现属性**传的
  （每条线一个色），而 CSS 声明压得过呈现属性 —— 一写 `fill`，六个标签会全变同一个颜色，
  不报错、不崩，只是"看着怪"。

高亮行的 `padding: 0 5px` 与 `margin: 0 -5px` 是**数值相抵**的：底色块往外扩 5px 的同时横向对齐分毫不动。
提示框里各行的小圆点必须严格在同一列上，错开一点就会被看出来（`tools/test_duality.js` 有断言守着这一对值）。

### 取数节奏

**一句话：前端零轮询、一切按需；服务端 30 分钟缓存兜底。**

| 层 | 频率 | 说明 |
|---|---|---|
| 浏览器 | **只在进页面时取一次** | `mount()` 里一个 `load(false)`，之后**没有任何取数定时器** |
| 切分组 / 切范围 / 勾标的 / 缩窗口 | **不取数** | 分组是同一份数据里换一批标的，区间是前端裁的（见下面「取舍 3」），都只是重画 |
| 页头「立即刷新」 | 点一次取一次 | id 是 `duRefresh`（**不是** live 页的 `btnRefresh`，见下）。带 `?force=1`，**唯一能穿透服务端缓存的入口**；取数中禁用并显示「刷新中…」，取完复位 |
| 60 秒心跳 | **本页没有** | 页头只剩「取数时间」，没有市场状态要刷，所以不启动心跳（2026-10-08 与徽章一起去掉） |
| 服务端内存缓存 | `CACHE_TTL = 1800`（30 分钟） | 窗口内所有请求（多标签页、多设备）拿到同一份，不碰外部接口 |
| 外部源链 | 仅缓存未命中时 | 11 只标的**并发**取（不是排队）；每源 `TIMEOUT = 8` 秒、最多 `RETRIES = 3` 次、退避 `0.5 × attempt` 秒 |
| 源失败记忆 | `SRC_MEMORY_TTL = 1200`（20 分钟） | 失败的源在这 20 分钟里被压到备源后面，过期自动复位（不复位就是永久降级） |
| 落盘缓存 | 每次成功都写 | `data/duality_cache.json`；三个源全挂时退回来显示，标 `stale`，页面出红条说明 |

之所以敢这么"懒"：**日线一天只新增一根**，盘中重取的边际信息只有"今天这根还没收盘"。
30 分钟缓存对这份数据绰绰有余。真正的风险在另一头 —— **请求打密了会被东财限流封 IP**
（2026-10-08 实测：连着调几次之后整个域名对本机掐连接，连状态码都不给），所以缓存宁长勿短。

想立刻拿最新一根（比如盘中想看今天的走势），点右上角「立即刷新」即可。

### 三个关键取舍

**1. 纵轴是涨跌幅（%），不是绝对价格。**
纽约金 4145 美元/盎司、紫金矿业 29 元 —— 把原始价格画在同一根 Y 轴上，
紫金会是一条贴着底边的直线，图上什么都看不出来。所以各条线共用 0% 这条基准线，
绝对价进表格和悬停提示。

**2. 基准取「区间开始前最后一个交易日」的收盘价，不是"区间内第一根"。**
不同标的的区间首日未必是同一天（中美假期不同），各拿各的首日当基准，
各条线的起点就对不齐了 —— 而那正是这一页要横向对比的东西。

**3. 区间由前端裁，切范围不重新取数。**
后端一次给全部（约 800 根 × 11 只，gzip 后十几 KB），7/30/90/180/年初至今/自定义
全在浏览器里完成。代价是首屏多搬十几 KB，换来的是点标签零延迟 ——
否则每次切换都要等两秒，还得为"请求回来时用户已经点了下一个标签"写一套竞态处理。

### 不补点

中美假期不同，某一天可能只有一边有数据。折线**直接跨过缺口相连**（时间轴的正常表现，
斜率会缓一点），不在缺口处伪造一个"当天没交易但假装有"的价格。

由此而来的一个真实边界：**长假刚过时，「过去 7 天」里 A 股可能只剩 1 个交易日**
（2026-10-08 国庆后第一天就是如此：A 股只有 10-08 一天有数据，几只金矿股在图上各是一个孤点）。
这不是 bug，但读者只会看到"线呢？"，所以图上会出一条黄条，点名是哪几只、说明是休市、
并给出出路（把范围放宽）。判据写在 `paintChart()` 里，接近全量用例
`tools/test_duality_render.js` 钉住。

### 数据源：一条源链，谁通用谁

`duality.py` 里每个标的配一条源链，**依次尝试**：

```
纽约金        东方财富(101.GC00Y) → 新浪外盘期货(GC)
纽约银        东方财富(101.SI00Y) → 新浪外盘期货(SI)
A 股九只      东方财富(1.60xxxx / 0.00xxxx) → 腾讯(前复权日线 shXXXXXX / szXXXXXX)
```

> 黄金 / 白银走的是**同一个**新浪外盘接口（`...getGlobalFuturesDailyKLine`，按 `symbol` 取品种），
> 所以 `duality.py` 里只有一个 `_src_sina_fut`，源名按品种给准（`COMEX 黄金` / `COMEX 白银`）——
> 写死"黄金"的话白银那只会顶着黄金的名字走一路，而且不报错。

- **东方财富放前面**：一个请求同时覆盖期货和股票，字段最全（连当日涨跌幅都给），
  正常时十一只标的并发、2 秒完成。
- 但它是**会限流的**。2026-10-08 调试期间短时间打了三十多次之后，整个域名对这台机器
  连续十几次直接掐连接（`Remote end closed connection`，连 HTTP 状态码都没有），
  而同一时刻新浪、腾讯完全正常。真实使用不会这么打，但没有备源就是单点依赖。
- 腾讯的日线必须用**前复权**（`qfq`）：矿股分红除权不罕见，不复权价画出来的
  "过去 90 天跌了 8%"可能有一半是除权造成的。
- 新浪那个外盘接口一次返回 2016 年至今的全量（约 390KB），这里只截尾部 800 根。

**失败记忆**（`_SRC_FAIL`）：某个源连续失败后会被排到队尾，免得每次开页面都先花几秒
去撞一堵已知的墙。**它带 20 分钟保鲜期** —— 没有保鲜期就会死锁：主源一旦被压到备源后面，
备源每次都成功，主源永远等不到清零计数的那次成功，"这次限流"就变成了永久降级。
`tools/test_duality_source.py` 专门钉这两条（离线，用桩函数换掉真实源）。

**落盘缓存**（`data/duality_cache.json`）：内存缓存只顶 30 分钟，重启就没了。
盘上留一份上次成功的，三个源同时不可用时按"这是几点几分的数据"降级显示 ——
页面会出一条**红条**说明本次取数失败、下面不是最新行情，而不是把旧数字当新的端上来。
（同一套降级思路见 `night_close.json`。）

### 取数按钮为什么在页头（以及为什么 id 不叫 btnRefresh）

2026-10-08 按用户要求：这个按钮原先在内容区、叫「重新取数」，现在搬到**页头右上角**、
改名**「立即刷新」** —— 和 live 页那个按钮长得一样、叫得也一样。

**但 id 不同**：页头这个是 `duRefresh`（live 的是 `btnRefresh`）。这不是洁癖，是防串台：
`shell.js` 里 `btnRefresh` 绑的是 `/api/refresh`（重抓一轮夜盘行情），而且
**只在夜盘进行中可点**（`paintRefreshBtn`：场外就灰掉）。这一页的按钮走的是
`/api/duality?force=1`，任何时刻都能点。共用 id 的话，那套"夜盘才可用"的逻辑
哪天扩到 duality 分支，就会在不声不响中把这个按钮灰掉、或改掉它的文案。

**绑定不在壳里做**，由 `duality.js` 的 `bindHeaderRefresh()` 自己挂 —— 谁管数据谁绑事件；
壳只负责把按钮画出来（`renderHeader` 的 duality 分支）。⚠️ 时序：那一句必须在
`Shell.mount(...)` **之后**调用，页头 DOM 是那一步渲染的；提前调用时
`$("duRefresh")` 返回 `null`，`addEventListener` 当场抛 `TypeError`、后面的初始化全跳过。

搬按钮要盯**两头**：新按钮加上去只是其一，**内容区那个必须连 DOM 带绑定一起删** ——
只删 DOM 的话 `$("dpReload")` 返回 `null`，`bindPanel` 里那行 `addEventListener`
当场抛 `TypeError`，面板初始化中断，页面只剩一行时间范围、图和表都不出来。
所以 `tools/test_duality.js` 里有断言**读源码**同时守这两头（不是读渲染结果 ——
用例里的 `$()` 是懒创建的，拿它判"元素不存在"是假命题）。

shell.js 里为此加了第四种 `mode: "duality"`（同 catalog：壳只给骨架 + 页头徽章 + 按钮，
数据由页面自己取。本页的页头徽章**只有「取数时间」** —— 见下）。

### 页头徽章为什么只剩「取数时间」

2026-10-08 按用户要求精简。原来三个并排：**市场状态**（开市中 / 休市中）、**数据截止**、
**取数时间**。砍掉前两个：

- **市场状态**说的是"现在美股开不开市" —— 对一页**历史日线**没有意义。
  这一页又不自动更新，开市与否不会让它变一个字；
- **数据截止**和 X 轴最后一天是同一个信息，图上本来就有。

改这类"删徽章 / 搬按钮"的活儿，要盯的是**两头**：DOM 删了之后 `$("duLatest")` 会返回
`null`，再赋 `textContent` 当场抛 `TypeError`（和页头删按钮后忘删 `addEventListener`
是同一个坑，本项目已经踩过三次）。所以 `paintHeaderBadges` 里读元素一律写成
`var el = $("x"); if (el) ...`，写入那段也跟着删干净；
`tools/test_duality.js` 里有一组断言**读源码**守着这几处（徽章 + 页头按钮 + 内容区按钮），
而且**断言前先剔掉注释** —— 踩过：注释里写了某个词（比如"不启动 statusTimer"），
`indexOf(...) < 0` 就当场假失败，守的是注释不是代码。

顺带：页头没有市场状态元素之后，那个 60 秒 `statusTimer` 就只剩白打 `/api/status`，
所以 duality 模式下一并去掉了（`mount` 的 duality 分支里注明了"要加回来时同步恢复"）。

### 版本握手

`server.py` 的 `DUALITY_SCHEMA` ↔ `static/duality.js` 的 `DUALITY_SCHEMA`。
对不上时页面直说「服务需要重启」并给出命令，**不会伪装成"这页没数据"** ——
后者是最坏的一种错：不抛异常、数据其实好好的，用户会跑去重跑生成脚本。
（同一套做法见「明暗对照」的 `BUSINESS_MAP_SCHEMA`。）

版本沿革（**加字段也必须升**，理由见 `DUALITY_SCHEMA` 处的注释）：

| 版本 | 改动 | 不升版本会怎样 |
|---|---|---|
| v2（2026-10-08） | item 多了 `marketCap` | 新页面把整列画成「—」、排序退回原样，看着像"这几只票没有市值" |
| v3（2026-10-12） | item 多了 `group`，顶层多了 `groups`（分组定义） | 新页面**一个分组都凑不出来**，图和表全空 —— 而它只是需要重启一下服务 |

> ⚠️ **加了这个接口之后必须重启服务**：`bash tools/start.sh --restart`
> （或双击 `tools/restart.command`）。旧的 `server.py` 不认 `/api/duality`，
> 页面会出黄条说明。纯静态文件的改动不需要重启，刷新即可。

### 不重启也能看效果：静态预览页

`/duality` 这个路由**要重启服务**才存在。而"改完想看一眼"是高频动作，
每次都让人去终端敲一条命令很别扭。所以另做了一个单文件预览页：

```bash
python3 tools/make_duality_preview.py     # → duality-preview.html（生成物，未入库）
```

它把三样东西打进一个 HTML：`static/` 下的**真实**前端代码（style.css / util.js /
icons.js / duality.js，logo 内联成 data URI）、`data/duality_cache.json` 的**真实**
数据快照（11 只标的 × 800 根日线，两个分组），以及两个桩 —— `Shell`（只画侧栏与页头，不取数）
和 `fetch`（把快照当接口响应）。所以预览页里**每一条线、每一个数字都是真的**，
只有"数据怎么送到页面上"这一段是桩。双击就能打开，不依赖服务、不依赖网络。

菜单文字不是手抄的，是从 `shell.js` 的 `NAV` 里抽出来的 —— 桩和真菜单各写一份，
以后加页面时必然对不上。

> 一处踩过的坑（2026-10-08）：`duality.fetch_all()` 落盘的 payload **不带 `schema`**，
> 那个字段是 `server.py` 的 `_duality()` 在返回前补的（前端靠它做版本握手）。
> 最初直接把缓存文件塞进桩里，页面就弹黄条「服务返回的结构与本页不匹配」，
> 看着像"桩写坏了"，实际是**快照少了一个字段**。现在生成脚本自己补 `schema`，
> 并会校验 `server.py` 与 `duality.js` 两处的版本号是否一致（不一致直接拒绝生成）。

验收用 `tools/test_duality_preview.js`：它**代替浏览器**把页内所有 `<script>`
按序执行，再检查图和表有没有真的出来（69 项，含**点一次分组 tab、验图和表整体换到白银组**）。日常回归用它就够 ——
node + DOM 桩几秒钟跑完，而且能断言到 SVG 字符串这一层。

但它**看不见 CSS**。2026-10-08「提示框永远不显示」那个 bug 就是两个桩用例全绿、
真机上才逮到的（见上面「提示框永远不显示」一节）。所以**悬停 / 指针类交互要另用
真实浏览器验**：CDP 发 `Input.dispatchMouseEvent`（不是页面内 `dispatchEvent`，
后者绕过浏览器自己的 mouseover 生成逻辑），判据是悬停前后**逐像素比对**，
而不是"元素存不存在"。

> 早先这里记的"工具会话里 headless Chrome 会卡死（等 7 分 49 秒无输出）"要修正：
> 那是 `chrome --screenshot` 那条路 —— 它根本不会把鼠标放到任何地方，
> 悬停类元素在它眼里永远是空的，看着就像"没输出"。走 CDP 正常，
> 实测 12–17 秒跑完全流程（连开关 Chrome 带取数渲染）。

### 用例

### 真机验证：`tools/hover_duality.js`（**不进 `test_all.sh`**）

上面四个跑的都是 **DOM 桩**，它们**看不见 CSS 层叠** —— 而"提示框永远不显示"那个 bug
恰恰只在 CSS 层叠里。所以另有一个真机脚本，用 headless Chrome + CDP 把三条对一遍：
**DOM 说有 → 层叠样式说可见 → 像素说画了**。

```bash
node tools/hover_duality.js                       # 默认打 127.0.0.1:8787/duality
node tools/hover_duality.js file:///.../duality-preview.html
```

它会自己切到 90 天（7 天里 A 股只有 1 个交易日、画不出多条线），逐条线**发真实鼠标事件**，
再在提示框区域做**悬停前后逐像素比对**（这一步是决定性的 —— 元素存在、样式可见，
都不等于它被画出来了）。退出码 0 = 正常。

不并进 `test_all.sh`：要开真浏览器、十几秒，还依赖本机装了 Chrome。
**改过悬停 / 标签 / 提示框 / 折线样式之后，手动跑一次。**
